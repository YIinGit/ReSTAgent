# 活动策划案初审

依据《2026活动部教案》第四讲至第九讲，对高一新成员提交的活动策划案做初审，
输出必改/建议意见，并写成 Word 批注版。

## 打开方式

- 主界面右上角 **策划初审**，或直接访问 `http://127.0.0.1:5731/campaign`
- 上传 `.docx` → 选活动类型与提交对象 → 开始初审

## 审查依据

| 讲次 | 内容 | 规则 |
|---|---|---|
| 第四讲 | 策划基础与需求分析（五条标准、五种活动类型、需求分析四步法） | R01 R02 R17 |
| 第五讲 | SMART 目标 + 资源整合（人力/物力/地力） | R07 R10 R11 R12 |
| 第六讲 | 流程设计（时间轴倒推法、留缓冲） | R04 R05 R18 |
| 第七讲 | **规范写作（重点）**：五板块齐全、语言受众维度 | R09 R03 R06 R14 R15 R20 |
| 第八讲 | 活动复盘（四维度评估） | R19 |
| 第九讲 | 创意孵化（联想矩阵法） | R16 |

规则库：`app/campaign/rules.json`（改这里即改判定口径，提示词里的速查表会跟着变）。

## 判定流程

```
docx → 段落编号 → 分块（单块约 6000 字）
     → 模型出 JSON（含 anchor 原文片段）
     → 校验：anchor 三级匹配 / 编造数字拦截 / 数量上限
     → 合并去重 → 结论由代码算
     → 导出 Word 批注 + Markdown 报告
```

### anchor 三级匹配

模型给的 `anchor` 是"从原文逐字复制的片段"，但实际经常有一字之差。所以定位采用三级：

1. **逐字**：完全一致，且能按 `occurrence` 区分重复出现；
2. **归一化**：去掉空格、统一引号破折号后再找；
3. **近似**：同段内 difflib 相似度 ≥ 0.9。

三级都不中，说明模型可能伪造了原文——这条**降级为建议**并挂到文末，绝不错位到别的句子。

### 结论由代码算

- `must == 0` → **通过**
- 缺 2 个及以上核心板块，或缺「流程」「危机预案」任一关键板块 → **退回修改**
- 其余 → **修改后通过**

核心板块由 `reviewer.missing_sections()` 自动识别：标题命中、板块名后紧跟表格、
正文出现「XX：」或「XX见下表」都算「有」。

### 防编造

`rewrite` 里出现原文没有的数字（如原文没写人数，模型却写「200 人」），
一律**丢弃改写内容**、只保留问题描述——不替策划人编事实。

## 导出

- **批注版 Word**：原文一字不动，每条意见写成 Word 原生批注，可在「审阅」窗格逐条处理
- **意见 Markdown**：可直接发给策划人

## 验证

```bat
python tests\campaign_samples.py    :: 生成 3 份测试策划案（合规/待修改/退回）
python tests\test_campaign.py       :: 离线单元测试，不调用模型
```

真实模型实测（`deepseek-v4.1-flash`）：

| 样例 | 结论 | 命中 |
|---|---|---|
| 样例1 合规 | 修改后通过 | 4 必改（流程时长与自述 90 分钟矛盾、"全体成员"未落人、机房容量与触发条件不一致） |
| 样例2 待修改 | 修改后通过 | 6 必改（目标不可衡量、时间待定、责任人缺失、预案空话等） |
| 样例3 退回 | 退回修改 | 缺流程/目标/危机预案 3 个板块 + 2 条必改 |

耗时：单份 60~90 秒（一次调用）。

## 已知边界

- 表格内的文字能读到、能计字，但批注只能挂在段落上，不能精确到表格单元格；
- 「体例」类问题（R20 编号连续、单位统一）判断较粗；
- 教案原文不随程序分发，只随规则库以提炼形式存在。
